Visão Geral da Arquitetura

Esta secção introduz a infraestrutura de desenvolvimento contornando os limites do Windows Host. Ao invés de usar o Docker Desktop sobre WSL2 (que falhava devido ao erro 1603 de registo e DISM corrompido), estabelecemos um motor Docker nativo num ambiente de Máquina Virtual Hyper-V Ubuntu pura, controlada via cliente SSH e integrada perfeitamente no VS Code.

💻

Windows Host

Executa o VS Code, a extensão Remote-SSH e o navegador de internet. Totalmente imune às falhas de registo anteriores.

⚡

Ponte SSH Nativa

Canal criptográfico que conecta o VS Code local diretamente à VM, permitindo desenvolvimento em tempo real.

🐧

Hyper-V Ubuntu

Máquina Virtual dedicada ao motor Docker. RAM otimizada para 2GB dinâmicos para contornar a falha 0x8007000E.

Eficiência da Virtualização: VM vs Container

A decisão de rodar os serviços (como n8n, bancos de dados, APIs) dentro de containers em cima da VM, e não criar várias VMs separadas, baseia-se na eficiência de recursos. O gráfico demonstra o consumo típico de arranque e de base.

Máquina Virtual Clássica: Virtualiza hardware. Requer Sistema Operativo completo por serviço.
Docker Container: Virtualiza apenas o software. Compartilha o Kernel da VM de base, arranca instantaneamente.

Erros de Infraestrutura Superados

ERRO DE ARRANQUE HYPER-V

Falha de Alocação (0x8007000E)

Ocorria ao tentar iniciar o Ubuntu com os 6GB padrão quando o Windows Host estava sobrecarregado. Resolvido ao limitar a RAM Inicial da VM para 2048MB com Memória Dinâmica habilitada.

ERRO DE REGISTO DO WINDOWS

Falha Crítica WSL (Erro 1603)

Inviabilizava a instalação do WSL2 e do instalador oficial do Docker Desktop. Superado ao desacoplar completamente o motor do Docker do Windows, delegando-o para a VM.

O Fluxo de Trabalho e a Imutabilidade

1. Imagens são Imutáveis

Uma imagem depois de gerada não pode ser editada. Se fizer modificações na sua API em .NET ou nos fluxos, terá de gerar uma nova tag de versão (ex: 1.1) e subir novamente.

2. Tag e Referência

O comando docker tag funciona como um link simbólico de atalho. Ele não duplica o espaço do ficheiro no disco, apenas cria um novo apontamento com o seu identificador da nuvem.

3. O Ciclo de Rollback

Se atualizar o seu container para a versão nova e o sistema falhar, o rollback é instantâneo: basta parar a versão nova e iniciar novamente a imagem anterior estável, sem necessitar de reparação rápida em código de produção.
